🌿 Installation CICADA

Configurez votre instance en quelques étapes

Avant de commencer : où sera la base de données ?

  • Dans Docker, sur ce serveur (le plus simple) : rien à préparer, l'installation crée tout.
  • Sur un serveur PostgreSQL existant — une autre machine, VM ou conteneur dédié aux bases (serveur mutualisé, comme à RNF) : la base doit être préparée d'abord sur le serveur de base, en terminal, par une personne qui y a les droits root. Une seule commande, fournie dans la section « Base de données » ci-dessous. Prérequis sur ce serveur : PostgreSQL 15 ou plus avec PostGIS installé, et à l'écoute du réseau.
  • PostgreSQL installé directement sur ce serveur-ci : pas encore pris en charge par ce formulaire ; choisissez la base dans Docker.

Pourquoi un terminal ? Créer l'extension PostGIS exige un super-utilisateur PostgreSQL, et autoriser ce serveur à se connecter se règle sur le serveur de base.

    Mode de connexion

    Un seul mode de connexion par instance, jamais les deux à la fois.

    Comptes CICADA : chacun se connecte avec l'email et le mot de passe de son compte CICADA (inscription et mot de passe oublié dans l'application).

    GeoNature / UsersHub (cas de RNF) : on se connecte uniquement avec son compte UsersHub. Le compte CICADA est créé à la première connexion et rattaché à son organisme UsersHub ; un compte CICADA existant est retrouvé par son email.

    Par la base, CICADA vérifie que le compte a un droit sur l'application CICADA dans UsersHub (directement ou par un groupe). Par l'API, GeoNature ne vérifie que le droit sur GeoNature lui-même, et rien du tout avec un GeoNature dont pypnusershub est antérieur à 3.3.
    Une seule adresse ; « localhost » si la base est sur ce serveur.
    CICADA vérifie lui-même les mots de passe : avec une base distante, leurs empreintes passent sur le réseau. « verify-full » demande le certificat de l'autorité dans /etc/cicada/usershub/ca.crt et USERSHUB_DB_SSLROOTCERT=/etc/cicada/usershub/ca.crt dans le .env.
    Colonne code_application de utilisateurs.t_applications. Seuls les comptes qui ont un profil sur cette application (directement ou par un groupe) pourront se connecter.
